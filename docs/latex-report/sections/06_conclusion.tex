This paper presented a case study on hardening an existing open-source microservices application. By establishing a stabilized Docker environment and a GitHub Actions CI pipeline, we created a reproducible foundation for quality assurance.

Our empirical results show that while standard unit testing provided a starting point, it left gaps in branch coverage (62.5\% covered). The introduction of Mutation Testing was critical in exposing these gaps, driving improvements in the domain layer where semantic logic resides. Complementing this, the integration of JMH microbenchmarks established a performance baseline, ensuring that increased rigor in logic verification did not come at the cost of computational throughput. Conversely, the attempt to introduce formal verification via JML highlighted a significant toolchain gap: modern frameworks like Spring Boot and Lombok are currently resistant to standard verification tools due to their reliance on runtime injection and bytecode generation.

Furthermore, the integration of security auditing tools (Snyk, GitGuardian, SonarCloud) demonstrated that dependability extends beyond code logic to include supply chain security and configuration management. However, these tools proved not to be ``set and forget'' solutions; they require contextual interpretation to distinguish between genuine risks (e.g., vulnerable dependencies) and false positives (e.g., intentional CORS configurations).

We conclude that for existing ``modern'' Java applications, a hybrid approach combining \textbf{Containerization}, \textbf{Targeted Mutation Testing}, \textbf{Performance Baselining}, and \textbf{Automated Security Auditing} offers the highest return on investment. While formal verification remains a specialized technique for algorithmic cores, the pragmatic path to dependability in web architectures lies in a rigorous, automated, and security-aware CI/CD pipeline.
